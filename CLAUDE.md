# Agent notes

For the workflow, read [CONTRIBUTING.md](CONTRIBUTING.md) and the
[documentation map](docs/README.md).

## Project facts

- Supported inputs are USA (XXH3-64 89ea0690f3e22201) and Japan Rev A
  (d10125abf640077f), both 8 MiB after byte-order normalization. A build includes
  Japanese code only when its ROM is supplied; release builds require both.
- The build runs N64Recomp and RSPRecomp, then compiles generated output with
  the hand-written port, N64ModernRuntime, RT64, and RecompFrontend.
- build.ps1 and build.sh define the Windows and Linux build paths. The patch
  inventory in patches/README.md defines the dependency patch boundary.
- Windows uses RT64 with Direct3D 12. Linux uses RT64 with Vulkan. macOS is
  not a supported target in this branch.

## Source boundaries

- RecompiledFuncs/ is generated by N64Recomp. Never edit it.
- RecompiledFuncsJP/ is the separate Japanese translation. Never edit it.
- src/aspMain.cpp is generated by RSPRecomp. Never edit it.
- scripts/gen_syms_toml.py generates aerogauge.syms.toml and aerogauge.us.toml.
  Do not edit either output by hand.
- The same generator with `--region jp` uses scripts/japan_rev_a.py to generate
  aerogauge.jp.syms.toml and aerogauge.jp.toml. Do not edit these outputs.
- Region selection occurs before game threads start. Native hooks use verified
  regional addresses; Japanese car records and ticker registers differ from USA.
- aspMain.us.toml is the hand-maintained RSPRecomp input.
- force_stub.txt is a hand-maintained translation fallback list.
- src/ contains hand-written port code and narrow game hooks.
- patches/ contains diffs against pinned dependency commits.

## Runtime rules

- Guest code uses N64Recomp memory helpers for guest RDRAM. Keep address,
  width, byte order, units, owner, timing, and failure behavior explicit.
- SDL calls belong on the SDL main thread. Translated game functions and port
  hooks run on their documented game boundary. RT64 owns display-list work on
  its graphics path.
- Direct guest-memory writes used by full-course geometry, the widescreen HUD,
  and save-state loading are fragile transitional bridges. Do not use them as
  the model for new APIs.
- The long-term direction is named source or decompiled game code, explicit
  source patches, stable symbols, and a versioned code-mod or mod interface.

## Ownership rules

- Keep game-specific behavior in this repository. Keep reusable dependency or
  renderer behavior in a small patch with an upstream comparison.

## Checks

Run the smallest relevant check. Documentation changes require:

~~~text
python -B scripts/check_docs.py
git -c core.whitespace=blank-at-eol,blank-at-eof,space-before-tab diff --check
~~~

The whitespace command spells the CI rule out because this repository's local
git config sets core.whitespace=cr-at-eol, which hides the CR that terminates
every line of the CRLF-dominant src/main.cpp. Add new lines to that file with
LF endings, or CI reports each added line as trailing whitespace.

Do not claim a build, game run, visual check, or reference-project playthrough
unless it was actually performed. Do not commit ROM data or generated output.
